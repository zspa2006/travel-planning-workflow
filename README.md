# 多人协同旅行规划平台

软件项目管理课程 · 第十三组。当前基线提供 **A 的旅行规划前端** 和团队联调设计。

[打开在线界面](https://zspa2006.github.io/travel-planning-workflow/)可直接浏览示例首页和旅伴聊天。可以直接发送消息，也可以引用旅伴的消息回复。发送的消息仅在当前页面显示。顶部「旅行工作台」可继续体验建房、加入和查看方案。

## 本地演示

需要 Node.js 22 或更新版本。克隆仓库后在仓库根目录运行：

```sh
npm start
```

打开 [首页](http://127.0.0.1:4173)，选择「旅行工作台」，输入任意演示昵称。

1. 创建房间，填写名称、目的地和出发、返程日期。保存个人预算、必去地点、饮食禁忌和节奏，刷新后核对数据。
2. 退出并换一个昵称，输入刚才房间的邀请码加入。重新打开该房间可看到两位成员，各自的偏好分别保存。
3. 输入示例邀请码 `SUZHOU`，在「行程与费用」切换候选 V2 与正式 V1，核对多日行程、交通、个人与共同费用。候选有一项待确认费用，正式版有已知住宿费用。
4. 新建房间会显示空行程状态。真实方案通过后端接口提供，点击「刷新方案」重新读取。

演示数据只存于当前浏览器。昵称切换用于走查交互，真实身份认证、跨设备持久化和真实行程生成需要 C–F 模块联调。演示房间和费用均为样例。

## 接入团队后端

用 `?api=/api` 或 `?api=http://localhost:8000/api` 指定 API 前缀。后端负责提供账号、权限及真实数据。当前字段和路由是供 C、E 评审的接入草案，集中在 [接口约定](docs/frontend-api.md) 和 [HTTP 适配器](frontend/api.mjs)。

## 规则与版本模块（E）

`rules/` 目录提供六类确定性校验、多数投票与版本发布守卫，纯函数实现，供 D（调度）、C（存储）、B（工作台）联调。

- 六类校验：预算、时间、营业、必去、饮食、数据可信度，返回结构化问题码与阻塞/警告级别；
- 缺价费用**不按 0 元**计入合计，标记为待人工确认；超预算不能发布；
- 一人一票，赞成门槛 `floor(N/2)+1`（5 人门槛 3 票），弃权不计赞成；
- 发布前版本守卫：旧任务不能覆盖新正式版本。

```sh
npm test            # 运行全部用例（含 rules 模块 21 个用例）
```
